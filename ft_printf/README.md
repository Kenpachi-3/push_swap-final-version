# Description
This project is about recoding the standard C library `printf()` function and learning the mechanics of variadic functions. After a successful submission, this project will be integrated into my custom `Libft` library so that it can be used to handle formatting outputs in all future C projects.


### Supported Specifiers
The library successfully handles the following format conversions:
* **`%c`** - Prints a single character.
* **`%s`** - Prints a string (handles `NULL` string protection).
* **`%p`** - Prints a memory address pointer in hexadecimal format.
* **`%d`** / **`%i`** - Prints a signed decimal integer (base 10).
* **`%u`** - Prints an unsigned decimal integer (base 10).
* **`%x`** - Prints a hexadecimal number in lowercase format (base 16).
* **`%X`** - Prints a hexadecimal number in uppercase format (base 16).
* **`%%`** - Prints a literal percent sign.

# Instructions

### Building the Library
To compile the source files and create the static library archive `libftprintf.a`, run the following command in your terminal:
```bash
make
```

### Maintenance Rules
* Remove temporary binary object files (`.o` files):
  ```bash
  make clean
  ```
* Remove object files AND the final compiled `libftprintf.a` library:
  ```bash
  make fclean
  ```
* Force a complete clean rebuild of the entire library from scratch:
  ```bash
  make re
  ```

### Usage in External Projects
To use `ft_printf` in your own C projects, include the header file in your code and link the static library during compilation:

1. Add the header to your C files:
   ```c
   #include "ft_printf.h"
   ```
2. Compile your project by linking `libftprintf.a`:
   ```bash
   cc main.c libftprintf.a -I. -o my_program
   ```

## Algorithm

When `ft_printf` receives a format string, it reads it character by character, 
left to right. The main loop checks each character — everything that is not a 
specifier is printed directly and added to the running character count.

When the loop encounters a `%`, it skips it and reads the next character to 
determine which specifier it is dealing with. That specifier is passed to a 
dispatcher (a switch statement) which calls the appropriate handler function. 
Each handler is responsible for fetching the correct variadic argument, printing 
it, and returning the number of characters it wrote. The main function adds that 
return value to the total count.

Each specifier was given its own dedicated function because they each deal with 
separate concerns — different logic, different types, and different edge cases. 
This makes the code modular, readable, and easier to debug. Where behaviour is 
similar, functions were grouped: `%x` and `%X` share one handler, and `%d`, 
`%i` share another.

Every handler returns an `int` representing the number of characters it printed, 
so the main function can maintain an accurate total to return at the end — 
matching the behaviour of the original `printf()`.
